SAPNDA

Contributing components to the DNA Web UI Kit

The DNA Web UI Kit is the shared Figma library designers use across SAP Business Data Cloud (BDC), SAP Analytics Cloud (SAC), and Datasphere (DSP). Working with the design system team, I designed, rebuilt, and documented components for the kit, focusing on consistency across products and on making components flexible enough that designers don't need to detach them. This project is under NDA, so details shared here are intentionally high-level.

context

One UI kit behind three products. Every gap shows up everywhere.

SAC, Datasphere, and Business Data Cloud are designed from the same UI kit, which builds on SAP's Fiori guidelines and UI5 component library. When a component is missing, inconsistent, or too rigid, designers on each product work around it in their own way, and the products drift apart.

I joined the design system team for the first part of my internship, working alongside the kit owners and taking components from requirements through design, specs, review, and documentation.

problem

Components that drifted between products, or pushed designers to detach them.

The same component could look different depending on the product. Creation items in BDC used different color tokens and corner radius than the ones in SAC and Datasphere. Some toolbars used custom page switchers that weren't part of the design system at all. And components like the Switch Group couldn't hold more items, so designers detached them to add more, which breaks the link to the library and lets future updates pass them by.

goals

Consistent across products, flexible enough to use as is, and accessible by default.

Each contribution had the same goals: one spec shared by all three products, properties and slots that cover real use cases so designers never need to detach, accessibility annotations built in, and documentation clear enough for any designer to use the component correctly.

process

Creation Item: one spec across three products

Creation items are the large "Create" tiles users see when starting something new. I rebuilt the base set so the "Create" header became a boolean property, added BDC variants, and moved all three products onto the same grid list item spec, with the correct list tokens and a 16px corner radius. I also cleaned up layer names and added accessibility annotations.

Two questions came up along the way. On color, I learned the item colors are chosen to stand apart from each other at a glance, not because they look harmonious, so I wrote that into the guidance. On keyboard navigation, UI5 and the Fiori keyboard guidelines disagreed on what the up and down arrows should do. I raised it with the DNA accessibility advocates, and we landed on left and right moving through items in order, with up and down moving between rows.

[Image: Creation Item before and after, across BDC, SAC and DSP]

Page Switcher: deciding whether to build at all

Some toolbars had their own custom pagination. Before designing anything, I collected every instance across the products and asked the kit owners whether designers should reuse the existing pagination component or whether the kit needed something new. We agreed on a Page Switcher subcomponent, which I designed with text properties for the current and total pages, a variant for active and disabled arrows, and documented logic, such as disabling the left arrow on the first page.

Switch Group: designing so designers don't detach

Designers were detaching the Switch Group whenever they needed more switches. I rebuilt it with slots, so a group can hold up to five switches with the Switch set as the preferred item, and added a guideline showing how to add more without detaching.

Smaller contributions

I also rebuilt the BDC App Start Page from SAC components, with interchangeable table and toolbar subcomponents, moved the System Information Bar from hard-coded hex values to design tokens and got approval to add it to the kit, and designed new chart icons, including a sunburst chart, stream graph, and word cloud.

outcome

Six contributions to the kit, shared across 3 products.

Creation Item, Page Switcher, Switch Group, App Start Page, System Information Bar, and a set of chart icons, each specced and documented for designers across SAC, Datasphere, and BDC. Full case study details are available on request.

reflections

Designing for designers

My users on this project were other designers. A component that technically works but gets detached has failed, so I started asking "what will someone need to change here?" before deciding on properties, variants, and slots.

Not every question has a documented answer

When UI5 and the Fiori guidelines disagreed on keyboard behaviour, there was no rule to look up. Bringing it to the accessibility advocates, with both options laid out, got us to a decision faster than picking one and hoping it held up in review.

Consistency comes from the spec, not the screenshot

Two components can look nearly identical and still drift apart over time if they use different tokens underneath. Aligning tokens, corner radius, and naming was less visible than a redesign, but it's what keeps three products in sync.
